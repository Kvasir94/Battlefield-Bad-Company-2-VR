## 8. Known pitfalls

- **Old docs still say the old rules.** Ignore their rules; use them only for facts.
  - `docs/HANDOFF.md` says "do not merge before a headset session". That is superseded by the merge-first directive.
  - `docs/2142-TRANSFER.md` is an append-only ledger. Stop appending to it.
- **The permission guard** refuses edits it reads as bypassing `AGENTS.md`, until `AGENTS.md` itself is replaced (item 2).
- **Three firing copies.** client1 (`+0x40`) is overwritten by Restore `0x6d71a0` hundreds of times per run, so never trust a client-only write. The server copy (item `+0x10`) is authoritative.
- **Auto-reload needs no input.** Step state 2 enters reload when loaded == 0, and it can fire on the server copy alone. The empty gate must stay, even under B.
- **Cross-thread reads.** Hooks run on sim threads, while our gather thread reads concurrently. That is the source of leases, cohort gaps and deferred reads. Do new logic **inside** the server-copy hook, from a lock-free event queue.
- **64-bit profile keys:** packing them into 32 bits broke F2000 (`ef6b3b2`).
- **Code density:** `Bc2ReloadFlowRuntime.cpp` (212 KB) and `Bc2Gameplay.cpp` (277 KB) pack many statements per line. Read carefully.
- **Run IDs** cited in commits refer to private reports on the owner's PC.
