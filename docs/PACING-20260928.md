# September 28 desktop pacing candidate

The user confirmed the corrected image looked solid and the dots appeared gone,
but quick head movement outpaced the image. The stable build delivered roughly
15 fresh pairs/second at 60 native frames/second; OpenXR reused original-pose
images between pairs. Preserve that checkpoint before further tuning.

Read-only inspection found BC2's native renderer stores SyncInterval=1 at+0x168.
The already uniquely discovered Present wrapper loads that interval, calls the
renderer-owned swap chain at+0x88, and passes native flags. Presentation was
waiting for the monitor even while feeding VR.

- Opt-in -UncapMirror maps to bit0x200 of the existing diagnostic config. It is
  accepted only with the bounded tracked stream; config size is unchanged.
- Validate live wrapper bytes against its unique discovery, renderer vtable,
  swap-chain device identity and DXGI module ownership before hooking Present.
- The shared D3D11PresentationPacing helper forwards the original HRESULT and
  flags, choosing interval0 only when the adapter says this is its active VR
  desktop chain. TEST calls, invalid intervals, unrelated swap chains and
  inactive capture are preserved. No native setting is written.
- No additional rendering, simulation, job-order, texture ownership or camera
  changes. End of sampling restores normal native sync behavior before the hook
  is disabled. Trampoline/module lifetime follows the established probe rules.
- The exact helper is tested through an x86 stdcall MinHook trampoline for return
  value, stack/argument preservation, TEST calls and unrelated/inactive chains.

23 x86 and22 x64 suites pass. Live160-pair check at1920x1080, asymmetric static
pose, async150ms:160consumed,0discarded/timeouts/GPU/camera/derived-context errors.

The extra inactive calls preserved native behavior. Cleanup and15s post-check pass.
