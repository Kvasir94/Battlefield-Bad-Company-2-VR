# Visible ammunition supply

This candidate places **one native SPAS shell at the existing left belt pickup
point** while the weapon is held and its native firing copies are idle. It is a
visible handle for the current reserve pool, not a literal display of the shell
count. It creates no item, changes no ammunition and adds no native resource.
Headset appearance and actual paired rendering at this new location remain
untested; the preview.4 archives are unchanged.

The standard belt contact is (-0.23, -0.55, +0.02) metres with an 18 cm pickup
radius. Presentation reads the same configured contact as the supply consumer.
Explicit BodyInventory uses its existing recentered body frame; legacy physical
reload uses the existing head-yaw frame. The runtime passes that choice explicitly.
Looking down does not pitch the belt, and body mode does not orbit it with head
yaw. Current head translation, native world scale and eye reference are retained.

The SPAS consumer publishes reserve, exact selected mesh, physical/native owner
and current right GunHold evidence. The belt is absent without reserve, during
an active reload/retirement, while a shell is held or pending, on cancellation,
or with invalid tracking/ownership. A full gun may show its real reserve; the
existing reload policy still refuses shell acquisition until ammunition is
needed. This change does not expand reload admission.

Rendering reuses the already verified `jntWpn_7` leaf and captured shell-center
calibration. It only replaces the known native collapsed idle pose in a private
palette. A natively visible reload/eject shell is never moved to the belt. All
other native bytes, SIMD padding, hands and hidden leaves are unchanged. Existing
held/guided shell previews, native cycle suppression, magazine/sight operations,
weapon visibility and free-hand/holster plans take priority. Both original Pack
callbacks recheck current supply/claim/owner/expiry and unchanged native source;
lost authority selects the exact ordinary palette. No simulation replay, new
graphics call, engine allocation, process-memory write or ammunition write is
introduced. Bounded `rig_publication.belt_ammo` counters record actual plans,
copies, pairs and fallbacks for the next native test.

The portable availability and frame code also describes magazine-shaped supply
handles, using the existing adapter's pool and per-object cost. **XM8 belt
magazines are not enabled.** Its one `jntWpn_6` leaf is needed by the attached,
removed or replacement magazine. Repositioning it to the belt would remove it
from the rifle; drawing several palettes does not create separate native meshes.
The code explicitly reports no independent magazine instance capability.

A practical next binding is a separately owned draw instance of the already
loaded weighted magazine section, preserving its material, resource references,
per-eye view lifetime and parent ownership. The current palette-copy hook only
replaces a skin palette consumed by an existing draw; it does not prove native
draw-list allocation, section-only submission or clone/destruction contracts.
Those must be observed before a belt magazine or multiple visible shells can be
enabled. No game mesh, texture or animation asset is copied into this candidate.

Validation covers the real body/pouch readers at rotated reference/head yaw,
crouch and native scales 1/100; source/claim/owner/expiry rejection; native-visible
leaf protection; private byte isolation; both-Pack revocation; and the actual
SPAS consumer's idle-to-grab/active-cycle behavior. Existing accepted reload and
preview suites run alongside the new cases. Source, policy and compile checks
are not native or headset acceptance. Before admitting the candidate, inspect
both eyes while looking down, then grab/load a shell, fire, support-grip, stow,
switch to XM8, pause and recenter. No extra belt prop should survive those owner
or interaction transitions, and no native ammo change should occur from looking
at or displaying supply.
