# Independent belt props: disabled renderer candidate

This candidate gives the existing supply policy a separate render-only magazine or shell. It copies rigid triangles into its own vertex buffers, so it does not borrow the seated magazine bone, create a native weapon/entity, or change ammunition. The currently working native palette paths are unchanged. **Nothing connects this renderer to BC2's hooks or enables belt magazines yet.**

The portable extractor accepts an exact section descriptor and immutable CPU copies of VB0 and the selected index range. It checks indexed position/skin fingerprints, signed base-vertex arithmetic, stride/offset bounds, exactly one 255-weight owner per vertex, single-bone triangles and the expected selected-part triangle count. It reflects raw native Z **before** applying the captured canonical inverse bind, and reverses the copied triangle winding for that reflection. Canonical input retains its winding. The copied triangle list has recalculated normals; culling is disabled. It contains no textures, native shaders, materials or copied game assets in source.

Six measured LOD0 sections contain 502 scoped-XM8 magazine triangles and 120 SPAS shell triangles. The compiled extractor independently replayed installed bytes over stdin, with no exported mesh files; its resulting bounds agree with double-precision reconstruction. This is geometry evidence, **not** a current native draw binding or proof that the prop is visible in either game eye.

`BuildAmmoSupplyPropPose` uses the existing verified `AmmoSupplyVisualSample` and exact `AmmoSupplyAnchorWorld` pickup contact. An unavailable pool, occupied hand/item, changed GunHold, owner/equipment/space change, or original deadline expiry invalidates it. It is one availability handle, not a displayed magazine count. For scoped XM8, invert the measured `xm8_magazine_calibration::ItemFromHand` before passing it as `partFromContact`: the existing calibration maps the authored hand into the part, whereas this new argument maps the part into the pickup-contact frame. Tests put that authored contact back at the exact belt anchor, including rotated reference/head and 0.01/1/100/1000 native units per metre.

The D3D11 backend is default-disabled and requires an explicit current eye identity, transform, color/depth target and matching depth convention for every draw. The adapter must freshly validate the world/request/view, actor, native weapon/equipment, tracking space and input generation. Only one instance is allowed per eye/frame. Mesh replacement is transactional and bounded to eight sections/8192 triangles (576 KiB vertex data); native and copied CPU resources are never retained by Upload. The renderer owns immutable GPU buffers and one private context-state object. Construction, upload, drawing and destruction must all occur on the owning native graphics thread.

The backend requires D3D11.1 context-state swapping, preserving the device's SINGLETHREADED flag. It swaps to private state, draws with a simple solid material and read-only depth, clears its own state to release borrowed world targets, then restores the saved native state on every return. There is no manual partial-state fallback. Microsoft documents both the [complete context-state swap](https://learn.microsoft.com/en-us/windows/win32/api/d3d11_1/nf-d3d11_1-id3d11devicecontext1-swapdevicecontextstate) and [matching thread-model requirement](https://learn.microsoft.com/en-us/windows/win32/api/d3d11_1/nf-d3d11_1-id3d11device1-createdevicecontextstate). **Active asynchronous queries are not switched**, so integration must first establish a boundary outside native query/draw scopes. All immediate-context work must remain on [one owning thread](https://learn.microsoft.com/en-us/windows/win32/direct3d11/overviews-direct3d-11-render-multi-thread-intro).

## Validation and next integration boundary

- x86 and x64: ten CPU groups pass. The actual backend and manual GPU fixture compile/link with `/W4 /WX`; no GPU/device initialization was executed. Geometry replay passes all six installed sections on both architectures.
- `RigidPropGpuTests.exe` is an **unrun manual WARP fixture**, never registered with CTest. It checks an actual two-eye draw plus restoration of native RTV, conflicting SRV, viewport and topology. It is not native-game or headset acceptance.
- The CMake operation builds isolated libraries plus CPU tests. It does not link the backend into BC2NativeProbe or add a launch option.
- `Bc2ReloadDrawCapture::Poll` currently has temporary immutable VB/IB readback bytes immediately before `FingerprintReloadDraw` and releases them afterward. That is the possible extraction seam, but it currently admits SPAS shell/ACOG counts, not XM8 magazine sections. Extend a **bounded diagnostic** only after joining the selected mesh, exact rig/part inverse bind and current native draw/eye owner. Matching a triangle count or this asset fingerprint alone is insufficient. Consume the copied bytes before their staging owner releases them.
- A fresh per-eye supply source and physical-to-native weapon mapping must accompany the renderer call. Current `BeltAmmoTracking` is SPAS-specific; no new magazine source publication was fabricated here. Existing held/guided/seat/holster/menu/vehicle/tracking priorities still need composition in the eventual native adapter.
- Verify the real eye RTV/DSV, depth convention and projection at the chosen post-native draw boundary. This backend deliberately supports single-slice, single-mip Texture2D targets only; unsupported layouts fail closed. A failed draw can have rendered earlier sections, but restores context state and does not claim paired success.
- Native checkpoint/detach resource cleanup, material fidelity, both-eye depth/occlusion, pickup alignment and headset visibility remain unverified. No game, process, input, SteamVR or GPU actions were performed for this candidate.
