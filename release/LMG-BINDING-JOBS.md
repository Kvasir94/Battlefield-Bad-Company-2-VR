# LMG binding tools

These source-only tools prepare evidence for manual reload bindings. They do not enable LMG reloads, select a weapon, send input, install hooks, or grant ammunition. Generated installed-game metadata and native observations are private local outputs and are not included in source or runtime archives.

- `tools/inspect_lmg_common.py` reads only the supplied installation's exact `Dist/win32/levels/mp_common/level-00.fbrb`. The standalone parser permits at most 640 MiB of declared/decompressed payload for that archive, then restores the ordinary 512 MiB limit. Streaming chunks remain bounded to 1 MiB and selected resources to 32 MiB. Only typed LMG scalar/reference metadata is exported; mesh and animation payloads are not selected.
- `tools/build_lmg_jobs.py` joins exact authored configuration, body-mesh identities and existing family work plans. Different scoped/campaign/upgrade definitions are not collapsed by native weapon Name. A native bulk reload enum does not prove a belt, cover sequence or detachable magazine. Every generated job remains observational and disabled.
- `tools/capture_lmg_native.py` is an explicitly invoked, read-only observer. It requires `--executable`, `--pid`, `--tools`, `--jobs`, `--resource`, and `--output`. The executable path is passed to both disk-signature inspection and process-path validation. No developer installation or local launcher configuration is assumed by this command. It observes for at most 20 seconds, with a requested sampling interval of at least 20 ms.

The observer requires the exact selected asset name **and** configuration path. Each row checks client/server configuration relationships, three distinct firing objects, repeated client state, and unchanged ownership. Later rows must retain the initial actor/inventory/item/configuration/firing cohort; a changed owner is recorded as rejection, not folded into the original run. Native counts may progress. Structural external reads are neither an atomic simulation snapshot nor a native transfer/hold acknowledgement. Same-address replacement cannot be ruled out by external pointer equality alone.

The existing `capture_reload_state.py`, `capture_reload_server.py`, and `read_bc2.py` remain the signature/reflection-verified reader dependencies. The LMG entry point supplies its explicit executable instead of using the older reader's default path. Importing the LMG module or running its synthetic tests never opens a process. Its capture entry point is not part of any automatic test or launch flow.

Run `python -B -m unittest discover -s tests -p test_lmg_jobs.py` for the portable synthetic contracts. Actual installed coverage and timings must be generated locally with the tools; tests do not depend on saved game metadata, local absolute paths, or live game access.

For a future native trial, first select a genuinely available campaign LMG in ordinary gameplay and establish a positive partial clip. The tool prints readiness only after a coherent configuration and authored body-mesh observation; it never presses Reload. Record the ordinary reload, exact same ownership, effective counts, raw named weapon/hand bones, and native phase transitions before attempting any hold or interaction binding. A later hold/transfer/cancel trial needs its own code and ownership proof. The short legacy `SupportReload` schedule is not sufficient evidence for a complete long belt-fed reload.

The authored mechanism batch now supplies measured part motion and candidate cover/box/drum frames across all seven body models, plus six complete same-frame hand/part contacts across five models; see [LMG-AUTHORED-MECHANISMS.md](LMG-AUTHORED-MECHANISMS.md). This is offline authored evidence. Remaining work includes role/contact acceptance where gaps are recorded, partial-versus-empty order, native gate/abort/refill/ready receipts, and lifecycle restoration. MG36 and XM8 LMG follow detachable-magazine investigation; their stricter magazine grasp validation remains unresolved. No LMG manual reload is enabled by these tools.
